# 01: Replace ESLint with oxlint

**What to build:** `pnpm lint` runs type-aware oxlint and Prettier, and ESLint is gone from the workspace. Touches the root and the `api`, `web` and `contracts` packages (config and lint fixes only; no behaviour change). Spec: [spec.md](../spec.md), sections "Implementation Decisions" (Linting, Fixing the first run) and "Testing Decisions".

Rules this Ticket needs:

- One root oxlint config with per-package overrides, type-aware through `oxlint-tsgolint`. Prettier stays; `pnpm lint` still runs `prettier --check`. The shadcn UI folder and build output stay ignored.
- `api` and `contracts`: every rule in the maintainer's reference config (`nguyenhothanhtam0709/nestjs-test`, read from the local clone at `~/tam/learning/nestjs-test`, file `.oxlintrc.json`; it is a private repo) plus every rule this repo enforces today.
- `web`: today's rules plus the Vite template's react rules (`rules-of-hooks`, `only-export-components`), with plugins `react`, `typescript`, `oxc` and `import`. Without `explicit-function-return-type`, `max-lines-per-function` and `explicit-module-boundary-types`.
- Test files keep today's relaxations (non-null assertions and type assertions allowed).
- Each current custom ESLint rule becomes a native oxlint rule: the `dangerouslySetInnerHTML` ban (`react/no-danger`), named exports only (`import/no-default-export`), the `forwardRef` ban (`no-restricted-imports` with import names), the `node:` built-in import rule, the `class-validator` and `class-transformer` ban, `no-console`, the `process.env` restriction, no type assertions, and typed `no-floating-promises` and `no-misused-promises`. If any current rule has no oxlint equivalent, stop and ask; do not add a package to cover it.
- Thread limit: every script that calls oxlint runs `GOMAXPROCS=2 oxlint --type-aware --threads=2 ...` (decided by the maintainer). Verified: `--threads` alone does not limit the type-aware helper; `GOMAXPROCS` does (0.40 s wall at 2 against 0.22 s unset, same CPU time). Do not use `GOMEMLIMIT` and do not add a package such as `cross-env`. Run lint per package in sequence from the root script. Measure peak memory and time on this repo (`/usr/bin/time -l`). Spec: "Thread limits".
- `complexity` and `max-lines-per-function` are warnings in the reference. Fix them with the errors. Do not use `--deny-warnings`.
- Fix every error and warning where possible. An unfixable error gets `// oxlint-disable-next-line <rule> -- <why>` and a line in a root `fix-lint.md` (location, rule, reason).
- Check which disable-comment forms oxlint honours, then rewrite the lint-disable guidance in `docs/conventions/general.md` and the lint command description in `docs/workflow/setup.md` to match. Update package `AGENTS.md` files if they name ESLint. Files generated by the mattpocock skills are not edited without asking.

**Allowed packages:** add `oxlint@^1.94.0` and `oxlint-tsgolint@^7.0.2007` at the root; remove `eslint`, `@eslint/js`, `globals` and `typescript-eslint` from the root. Remove `eslint.config.js`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `pnpm lint` exits 0 on a clean tree, using type-aware oxlint plus `prettier --check`
- [ ] No ESLint package or config remains in the workspace
- [ ] Every oxlint invocation uses `GOMAXPROCS=2` and `--threads=2`, lint runs packages one at a time, and the PR shows peak memory, time and the type-aware pass's observed CPU use
- [ ] `api` and `contracts` use the full reference rule set plus today's rules; `web` uses today's rules plus the react rules, minus the three excluded rules
- [ ] Each ported custom rule fails on a deliberate violation (default export, `dangerouslySetInnerHTML`, `forwardRef`, a bare `fs` import, a `class-validator` import, `console.log`, `process.env`, a type assertion); the violation is reverted afterwards
- [ ] Every error and warning is fixed, or bypassed with a reasoned disable comment that has a matching line in `fix-lint.md`
- [ ] The docs that named ESLint or the old disable comment are updated
- [ ] `pnpm typecheck`, `pnpm test` and `pnpm docs:check` still pass, with no behaviour change

**Verification:** run the deliberate-violation checks above once and record the results in the PR. No new test files. No browser check (no UI change); the existing web behaviour tests cover the lint-driven source edits.

**Out of scope:** replacing Prettier with `oxfmt`; adding `--deny-warnings`; paying down the debt recorded in `fix-lint.md`; TypeScript 7 or Node 26.
