# 03: Build, run and test api and contracts through ttsc

**What to build:** `api` and `contracts` compile, typecheck and run through `ttsc`, with the reference repo's build configs, scripts and Vitest setup. `web` is not compiled by `ttsc`. Touches the root and the `api`, `web` and `contracts` packages. Spec: [spec.md](../spec.md), sections "Implementation Decisions" (tsconfig, Scripts, Vitest) and "Testing Decisions".

Rules this Ticket needs:

- Reference: the maintainer's `nguyenhothanhtam0709/nestjs-test` (private; read from the local clone at `~/tam/learning/nestjs-test`: tsconfigs, `package.json` scripts, Vitest configs).
- `api` and `contracts` run typecheck, build and clean through `ttsc`. `web` keeps plain `tsc --noEmit && vite build`.
- `api` overrides the target to `esnext` and adds `paths` with one explicit `@<folder>/*` entry per source subfolder, plus the `@ttsc/paths` transform. Existing relative imports are not rewritten. `contracts` has no alias, no `paths` and no `@ttsc/paths`, and keeps its target.
- `api` and `contracts` each get a dev build config and a production build config extending it. Production turns on source maps and comment removal and turns off declaration output and incremental builds, except that `contracts` keeps `declaration: true` because it exports its types.
- Scripts: names stay (`typecheck`, `build`, `lint`, `test`). `build` equals the reference's `build:prod`; add `build:dev` and `build:clean`. `api` `dev`, `db:migrate` and `db:seed` run the TypeScript source through `ttsc/register` (no build first); add `start:dev`, `start:debug` and `start:prod` (`start:prod` runs the built output). Add `format:check`, `lint:fix`, `test:watch`, `test:cov` and `test:debug` per package where they apply. No `tc` alias, no `test:e2e`. Root aggregate scripts keep working.
- Vitest: `web` and `api` use `resolve.tsconfigPaths: true`, replacing the manual alias in `web`. Try removing `unplugin-swc` and `@swc/core` from `api`; remove them (and the `@swc/core` entry in the pnpm build-script allow list) only if the full `api` suite passes without them. Otherwise keep them and say why in Comments. `api` keeps its global setup, setup files, timeouts and serial file execution. Vitest stays on version 5.
- Thread limit: every script that calls `ttsc` uses `--checkers 2` (decided by the maintainer), including `ttsc/register` in the dev and db scripts if it accepts the flag; if it doesn't, say so in Comments and ask whether `GOMAXPROCS=2` should be used for it instead. Do not use `GOMEMLIMIT`. Verified on a 600-file project: `--checkers 2` took 0.26 s against 0.25 s by default, with memory about the same. Measure on this repo (`/usr/bin/time -l`) and put the numbers in the PR. Root aggregate scripts run packages one at a time. Spec: "Thread limits".
- Update docs that name the old scripts or flow (`docs/workflow/setup.md`, package `AGENTS.md`, the browser check doc if its commands change). Files generated by the mattpocock skills are not edited without asking.

**Allowed packages:** add `ttsc@^0.37.2` to `api` and `contracts`; add `@ttsc/paths@^0.37.2` to `api` only; add `@vitest/coverage-v8` at the Vitest 5 line to the packages that get `test:cov`. Remove `unplugin-swc` and `@swc/core` from `api`, only if the `api` tests pass without them.

- `ttsc/register` (0.37.2) takes no `--checkers`: it is a Node `--import` hook that calls `prepareExecution` with no checker option (only `ttsx` parses `--checkers`), and I found no environment variable for it. So `dev`/`start:*`, `db:migrate` and `db:seed` run it with the default thread count. Question: add a `GOMAXPROCS=2` prefix to those scripts (as the Spec does for type-aware oxlint), switch them to `ttsx --checkers 2`, or leave them? Recommendation: `GOMAXPROCS=2`. This is the only open item.
- SWC removed: the full `api` suite (36 files, 323 tests, real Postgres) passes on Vitest's own transform with `resolve.tsconfigPaths`, so `unplugin-swc`, `@swc/core` and the allow-list entry are gone.
- `ttsc --noEmit` on this repo, 3 runs each (macOS): api `--checkers 2` 0.60 s / 362 MB, default 0.60 to 0.68 s / 362 MB; contracts 0.16 s / 125 MB with the flag, 0.16 s / 131 MB default.
